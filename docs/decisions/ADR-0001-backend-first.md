# ADR-0001：后端优先、API 驱动、契约先行

- 状态：已接受
- 日期：2026-10-24

## 背景

原计划前后端同期推进，容易产生"接口随页面需要临时改动"的问题，导致后端不稳定、前端返工，也难以支持未来由其他 AI Agent 独立重构前端。

## 决策

采用**后端优先、API 驱动、契约先行**的开发模式：

1. 先梳理需求、分析旧站、冻结数据库设计与 OpenAPI 契约（P1）。
2. 再实现完整 Go 后端（P2）。
3. 最后实现完整 Vue 前端（P3），前端仅依赖 `/api/v1` 与 OpenAPI。
4. UI/主题完善（P4）与部署发布（P5）随后进行。

## 理由

- 契约先行让前后端可并行且互不阻塞。
- 后端稳定后，前端不会因接口变动反复返工。
- 为"其他 Agent 只改 `frontend/`"提供明确边界。

## 影响

- P1 阶段需要额外投入文档与契约编写时间。
- 后端必须先于前端完成，前端开发在 P2 完成前依赖 Mock 服务。
- 任何接口变更都走契约流程（见 ADR-0004）。

## 备选方案

- **前后端并行**：短期看似更快，但接口不稳定导致返工，且不利于前端独立重构。
- **前端优先**：与后端优先原则冲突，且不利于数据一致性。
