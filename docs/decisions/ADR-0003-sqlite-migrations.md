# ADR-0003：SQLite + 版本化迁移 + 升级前备份

- 状态：已接受
- 日期：2026-10-24

## 背景

应用为单实例、单管理员场景，需要免运维的持久化方案，并且必须保证升级不丢失用户数据、升级失败可回滚。

## 决策

1. 使用 **SQLite**（WAL 模式）持久化到 `/data/app.db`。
2. 使用 **版本化 SQL 迁移**（`embed` 打包，`schema_migrations` 记录），启动时自动执行。
3. 迁移失败时**拒绝启动**，避免半迁移状态运行。
4. 升级脚本在修改应用前**先做一致性备份**（`VACUUM INTO` / Online Backup API + 上传目录）。
5. 可逆迁移提供 `down`；不可逆迁移依赖升级前快照恢复。

## 理由

- SQLite 单文件、免配置、备份简单，契合自托管场景。
- 版本化迁移保证结构演进可控、可测试。
- 升级前备份 + 失败即停，保证数据安全底线。
- 不直接热拷贝 WAL 数据库单文件，避免备份损坏。

## 影响

- 迁移文件必须"只增不改"，已发布迁移不可修改。
- 需要维护迁移测试与备份/恢复测试。
- 当出现多实例/高并发需求时，再评估迁移到 PostgreSQL（V2.0 不做）。

## 备选方案

- **PostgreSQL**：能力更强但运维成本高，单实例场景过度设计。
- **JSON 文件存储**：并发与一致性差，不支持事务与索引。
- **直接热拷贝数据库文件备份**：WAL 模式下可能得到不一致快照。
