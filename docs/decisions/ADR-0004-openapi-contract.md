# ADR-0004：OpenAPI 作为前后端唯一契约

- 状态：已接受
- 日期：2026-10-24

## 背景

项目需要支持"其他 AI Agent 只修改 `frontend/` 即可完成前端重构"。若接口依赖代码或口头约定，接手者必须阅读后端源码，无法达成该目标。

## 决策

- 以 `docs/openapi/openapi.yaml`（OpenAPI 3.x）作为**前后端唯一事实来源**。
- 接口变更先改契约，再改实现；契约经 lint 校验。
- 前端使用 `openapi-typescript` 从契约生成类型，使用 Prism Mock 无后端联调。
- API 路径统一 `/api/v1`，公开接口在 `/public/*`，鉴权接口在 `/admin/*`，认证在 `/auth/*`。
- 破坏性变更升级 API 版本并记录 ADR。

## 理由

- 契约自描述，接手者无需阅读后端源码。
- 类型生成减少前后端类型不一致。
- Mock 支持前端独立开发与调试。
- 明确的接口分级让权限边界一目了然。

## 影响

- 后端实现与契约必须保持一致（P2 需有契约一致性测试）。
- 契约变更需要流程与评审，短期略增加沟通成本。
- 需要引入 lint/mock/类型生成工具到开发与 CI 流程。

## 备选方案

- **代码即契约（Go 结构体生成文档）**：接手者仍需理解代码，且前端易与后端耦合。
- **口头/文档约定**：易漂移，不可自动校验。
