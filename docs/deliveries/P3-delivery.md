### 2.2 实际完成的开发任务

1. **API 客户端层**：`src/api/` 下按资源拆分（`auth`/`public`/`categories`/`bookmarks`/`admin`/`system`），统一 `client.ts` 负责 baseURL、Cookie、CSRF 头、错误归一化与文件上传。
2. **状态管理**：Pinia `auth`（会话状态）与 `site`（公开设置与导航树）。
3. **路由与守卫**：`/`、`/login`、`/setup`、`/admin/*`、404；未初始化强制进入初始化向导，管理路由未登录跳转登录页并携带 `redirect`。
4. **导航首页**：时钟、搜索引擎切换搜索框、分类分组与图标磁贴、公开数据加载与错误态、主题切换。
5. **搜索**：调用后端 `/api/v1/public/search`（防抖 250ms），失败时回退本地过滤；回车使用所选搜索引擎打开新标签。
6. **登录 / 初始化**：管理员登录、首次初始化向导（含密码一致性校验）。
7. **分类管理**：列表、增删改、公开/私有切换、拖拽排序 + 移动端 ↑↓ 按钮、删除二次确认。
8. **网站管理**：按分类筛选与关键词搜索、增删改、跨分类移动（编辑中改分类）、公开/私有切换、拖拽排序、图标上传/抓取/手动填写。
9. **系统设置**：站点标题、Favicon、默认主题、首页布局、默认新标签、游客访问开关、搜索引擎列表增删与默认项；修改密码。
10. **数据管理**：导出 JSON（浏览器下载）、导入（文件 → 预览 → 冲突策略 → 执行）、备份列表/创建/恢复、版本检查。
11. **响应式与主题**：CSS 变量主题（浅色/深色，本地覆盖优先），移动端 4 列磁贴、管理端导航横向滚动、触控排序按钮。
12. **交互修复（由真实联调发现）**：手动填写图标地址时自动同步 `icon_type=url`；保存设置后刷新站点信息使页头标题即时更新。

### 2.3 核心技术方案与架构决策

- **严格分离**：前端只通过 `src/api/` 访问 `/api/v1`，组件不直接 `fetch`，不依赖后端源码。
- **契约对齐**：`src/types/api.ts` 与 `openapi.yaml` 字段一一对应（后续可用 `openapi-typescript` 生成）。
- **无 UI 框架**：纯 CSS + CSS 变量，便于后续由其他 Agent 整体替换。
- **拖拽**：自研 `useDragSort`（原生 HTML5 DnD），桌面拖拽、移动端按钮，二者调用同一排序接口。
- **主题**：服务端默认主题 + 本地覆盖（`localStorage`），避免每次切换都请求后端。

### 2.4 与原定计划的差异及原因

| 差异 | 原因 |
| --- | --- |
| 搜索框同时具备"实时筛选 + 回车用引擎搜索" | 兼顾旧站习惯（引擎搜索）与现代体验（即时结果） |
| 排序仅在"选中具体分类且无搜索词"时允许拖拽 | 跨分类混合列表下拖拽语义不明确；跨分类移动改由编辑弹窗完成 |
| 网站列表分页按 100/页循环拉取 | 后端 `page_size` 上限 100，前端循环以完整展示 |
| 新增前端交互修复 2 处 | 由真实浏览器联调发现，非计划内 |
| 未引入 UI 组件库 | 用户要求"界面整洁、不追求高保真"，且便于后续重构 |
