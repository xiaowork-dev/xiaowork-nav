## 1. 阶段目标

新增**标签页式导航布局**（模式 B），并提供**两种布局的一键切换**：
切换即时生效、刷新后保持、与明暗主题完全独立、两种布局共享同一份分类与网站数据。

## 4. 实现的具体功能

### 4.1 模式 A：滚动模式（保持 P3 增强版）

所有分类纵向排列 + PC 左侧固定分类栏；保留原有渐变背景、搜索、主题与磁贴设计。

### 4.2 模式 B：标签模式（需求 4.2）

```
.page.page--tabs
├── AppHeader（含布局切换控件）
└── TabsLayout
    ├── .tabs-hero   居中时钟 + 居中搜索框
    ├── .tabs        顶部分类标签（首页 + 各分类，横向滚动，含网站数量）
    └── .tabs-panel  当前标签的网格磁贴（可自然滚动，不强制单屏）
```

- **默认「首页」标签**：在没有收藏/常用网站机制的前提下，合理的默认实现是"展示全部可见网站"；
  个性化常用网站留待后续版本（已在文档标注）。
- 分类较多时标签条**横向滚动**（隐藏滚动条），不会挤压页面或产生横向溢出。
- 标签模式**不显示**左侧分类栏。
- 独立背景：`.page--tabs` 在既有渐变之上叠加一层 accent 径向光晕，仍由主题变量派生，
  **不引入任何第三方图片**。

### 4.3 一键切换（需求 4.4）

导航页右上角的分段控件提供「滚动模式 / 标签模式」，点击后**立即切换、无需刷新**；
窄屏下只保留图标以节省空间。控件与主题按钮同一视觉体系。

### 4.4 布局与主题独立（需求 4.5）

两者是**独立偏好**：`useLayout` 只读写 `xn-layout`，`useTheme` 只读写 `xn-theme`。
四种组合（滚动×深/浅、标签×深/浅）均实测通过，切换任一方都不会影响另一方。

### 4.5 偏好持久化（需求 4.6）

| 场景 | 行为 |
| --- | --- |
| 未设置过布局的新访客 | 默认 `scroll`（或站点默认值） |
| 访客切换后 | 写入 `localStorage['xn-layout']` |
| 刷新页面 | 保持原布局（实测） |
| 重新打开浏览器 | 保持（localStorage 持久） |
| 主题偏好 | 不受影响（`xn-theme` 未被触碰） |

优先级：本地选择 > `settings.homepage_layout`（站点默认）> `scroll`。
后台设置的「默认导航布局」只影响**尚未选择过**的访客，不会覆盖访客已有选择。

### 4.6 功能一致性（需求 4.7）

两种布局共用：

| 共享项 | 实现 |
| --- | --- |
| 分类与网站数据 | 同一 `stores/site.ts`（一次 `/public/navigation`） |
| 公开/私有权限 | 服务端过滤，两种布局一致 |
| 网站排序 | 服务端返回顺序，两种布局一致 |
| 网站图标 | 同一 `IconImage` 回退链 |
| 站内搜索与外部引擎 | 同一 `useNavSearch` composable |
| 管理员登录状态 | 同一 `AppHeader` + auth store |
| 明暗主题 | 同一 `useTheme` + `data-theme` |
| 数据刷新 | 同一 store，增删改后一次刷新即两种布局同步 |

实测：标签模式「首页」显示 20 个站点，与滚动模式的 20 个完全一致；搜索在两种布局下结果相同。
