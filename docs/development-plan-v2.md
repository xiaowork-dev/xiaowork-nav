## 0. 本次调整的核心变化

相对于原方案（先搭前后端骨架、再补业务），本轮明确调整为：

| 维度 | 原计划 | 调整后 |
| --- | --- | --- |
| 开发顺序 | 骨架 → 业务 → 安全 → 迁移 → 部署 | **需求/API 冻结 → 后端完整 → 前端完整 → UI 完善 → 部署发布** |
| 架构模式 | 前后端同仓库、同期推进 | **后端优先、API 驱动、严格前后端分离** |
| 前端地位 | 与后端同阶段开发 | 可被其他 AI Agent **完全独立重构** |
| 契约来源 | 代码即契约 | **OpenAPI 3.x 为唯一契约**，先定契约后写代码 |
| UI/UX | 未明确 | 不单独做高保真设计，后端稳定后一次性实现功能完整且美观的前端 |

技术栈不变：Vue 3 + TypeScript + Vite / Go / SQLite / Docker Compose / GitHub Actions + GHCR。

## 1. 五阶段总览

| 阶段 | 名称 | 交付物 | 验收标准 | 依赖 |
| --- | --- | --- | --- | --- |
| **P1** | 需求梳理、契约冻结与项目初始化 | 需求清单、旧版参考分析、数据库设计、OpenAPI 规范、错误码表、可运行前后端骨架、Docker 工件 | 数据库 DDL 通过迁移测试；OpenAPI 校验通过；公开/鉴权接口边界明确；`go test ./...` 通过；前端可构建 | 旧站数据样本（旧站导入器部分） |
| **P2** | Go 后端完整实现 | 可运行的 Go 服务、单元/接口测试、迁移器 | 全部 P0 后端接口通过接口测试；`go test ./...` 通过；SQLite 迁移可重复执行；`/healthz` 正常 | P1 冻结的契约 |
| **P3** | Vue 3 前端完整实现 | 导航首页、管理后台、网站/分类管理、响应式布局 | 前端仅依赖 `/api/v1` 即可完成全部功能；对接真实后端可完成端到端流程 | P2 可运行后端 |
| **P4** | UI、交互与主题完善 | 主题系统、视觉打磨、动效、移动端体验 | 桌面/移动端视觉验收；主题切换持久化；无重大可访问性问题 | P3 |
| **P5** | 部署、更新与发布 | Dockerfile、Compose、脚本、GitHub Actions、GHCR、Release | 全新环境一键部署；旧版本升级数据保留；AMD64/ARM64 镜像可用；备份/回滚可用 | P2/P3/P4 |

阶段顺序可因依赖关系微调，但**必须遵循后端优先原则**：前端不得先于其依赖的后端接口实现。

## 2. P1：需求梳理、契约冻结与项目初始化（详细拆分）

目标：先确定"要做什么"和"接口长什么样"，再搭好可运行的前后端骨架，使后续业务开发有稳定地基。

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| P1-1 需求清单化 | `docs/requirements.md`（P0/P1 功能条目与优先级） | 每条需求可追溯到接口或页面 |
| P1-2 旧版参考分析 | `docs/legacy-analysis.md`（视觉/交互参考、迁移假设） | 明确标注"已确认"与"待旧数据验证" |
| P1-3 数据库设计冻结 | `docs/database-design.md` + `0001_init` 迁移 | 表结构、索引、约束、迁移策略通过迁移测试 |
| P1-4 API 规范冻结 | `docs/api-spec.md` + `docs/openapi/openapi.yaml` | 错误码、鉴权、分页、排序规则明确 |
| P1-5 错误码与状态约定 | 错误码表（见 API 规范附录） | 前后端对同一错误码处理一致 |
| P1-6 前端交接规范 | `docs/frontend-agent-guide.md` | 第三方 Agent 仅读该文档即可开始前端开发 |
| P1-7 契约一致性检查 | `docs/api-contract-review.md` | 覆盖全部 P0 功能，无缺口 |
| P1-8 项目初始化与后端基础架构 | Git 仓库、目录骨架、可运行后端（配置/SQLite/迁移/路由/中间件/健康检查）、前端骨架、Docker 工件 | `go test ./...` 通过；前端可构建；前后端可独立启动；`/healthz` 正常 |

**P1 完成定义**：以上文档齐备且相互一致；OpenAPI 可作为 Mock 服务启动；后端骨架可独立运行并通过测试；前端可独立构建。

## 3. P2：Go 后端完整实现

目标：后端功能完善、API 稳定、有测试、可独立运行。

| 模块 | 内容 | 验收要点 |
| --- | --- | --- |
| 基础设施 | 配置加载、日志、路由、中间件（CORS/限流/恢复/请求大小限制）、`/healthz` | 启动可访问，配置项有文档 |
| 存储层 | SQLite 连接（WAL）、仓储接口、事务封装 | 单测覆盖仓储 CRUD |
| 迁移 | 版本化迁移执行器（embed + `schema_migrations`） | 空库可建表；重复执行幂等 |
| 认证 | 初始化管理员、登录/登出、会话、改密、CSRF/Origin 防护 | 未授权无法改数据；初始化仅一次 |
| 分类管理 | 增删改查、排序、显隐 | 接口测试通过 |
| 导航项管理 | 增删改查、排序、跨分类移动、关键词、图标、打开方式 | 接口测试通过 |
| 搜索 | 服务端搜索（名称/描述/关键词） | 结果正确、有分页 |
| 系统设置 | 站点标题、Favicon、主题、搜索引擎、公开设置读取 | 读写一致 |
| 图标 | 上传、URL、服务端抓取（防 SSRF） | 恶意目标被拒绝 |
| 导入导出 | JSON 导出/导入（带版本、校验、预览、冲突策略）、旧站导入器 | 导入真实旧数据不丢分类/图标 |
| 备份恢复 | 在线备份（`VACUUM INTO`/Backup API）、快照列表、恢复 | 备份可成功恢复 |
| 静态托管 | Go `embed` 托管前端产物 + SPA fallback | 非 API 路径返回 `index.html` |

**P2 完成定义**：`go test ./...` 通过；接口测试覆盖所有 P0 端点；`openapi.yaml` 与实现一致。

## 4. P3：Vue 3 前端完整实现

目标：功能完整、与后端严格解耦、可独立启动调试。

| 页面/能力 | 内容 |
| --- | --- |
| 导航首页 | 分类分组、图标卡片、实时搜索、搜索引擎切换、响应式 |
| 管理后台 | 登录、初始化向导、站点设置、更新信息 |
| 网站管理 | 列表、增删改、拖拽排序、移动端排序替代、图标设置 |
| 分类管理 | 增删改、排序、显隐 |
| 数据管理 | 导入（预览/冲突）、导出、备份列表 |
| 基础架构 | API 客户端层、路由守卫、状态管理、错误处理、加载态 |

**P3 完成定义**：前端仅修改 `frontend/` 即可完成全部功能；`npm run build` 产物可由 Go 托管；开发模式可独立运行。

## 6. P5：部署、更新与发布

- Dockerfile 多阶段构建（前端构建 + Go 构建 + 精简运行镜像）。
- `deploy/compose.yaml`、`.env.example`、NPM 反代模式。
- `scripts/install.sh`、`update.sh`、`backup.sh`、`restore.sh`。
- GitHub Actions：`ci.yml`（lint/test/build）、`release.yml`（多架构镜像 + GHCR + Release）。
- 更新流程：备份 → 拉取 → 迁移 → 健康检查 → 失败回滚。
- **P5 完成定义**：全新 Linux 环境可一键部署；旧版本可升级且数据保留。

## 7. 交付与 Git 规则

1. 每阶段完成即生成交付文档：`docs/deliveries/YYYYMMDD-HHMMSS-<slug>.md`，并更新 `docs/PROGRESS.md`。
2. 首次绑定 GitHub 远程后，每个正式版本必须提交并推送；失败必须写明"未推送"。
3. 所有网站项目必须具备 Docker 一键部署能力。
4. 重要架构决策写入 `docs/decisions/`（ADR）。
5. 完成必要测试后方可宣布阶段完成。
